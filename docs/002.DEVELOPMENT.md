# 开发与验证

## 环境与启动

开发环境使用 Node.js 22 和 pnpm；扩展声明支持 VS Code 1.80+、Git 2.40+。尚未完成最低版本和 Windows/Linux 的兼容矩阵验证。先阅读根目录 `AGENTS.md`、[产品方向](007.PRODUCT_DIRECTION.md)、[项目状态](001.PROJECT_STATUS.md) 与当前 [稳定化计划](008.STABILIZATION_PLAN.md)。

```sh
pnpm install --frozen-lockfile
pnpm run compile
pnpm run build:esbuild
```

`compile` 做 TypeScript 类型检查并生成 `out/`；esbuild 生成扩展入口 `dist/extension.js`。两者不能互相替代。按 F5 启动 `Run Extension`，已有 watch 任务只自动打包，需要时另开 `pnpm run watch:tsc`。

打开界面只读取本地引用；只有“更新远端状态”主动 fetch。Git 服务与 VS Code UI 分离，Git 执行器可注入，文件监听只覆盖 Git 元数据。没有后台网络轮询或代理覆盖。

## Git 路径来源

扩展入口通过内置 `vscode.git` 的公开 API v1 获取 `api.git.path`，由 `src/gitPath.ts` 实施最多 2 秒的等待与取消处理，再注入 `ProcessGitRunner`。不等待仓库扫描，不调用 API 的 fetch/delete，不订阅仓库状态事件。API 不可用、禁用、激活失败或返回无效路径时使用 `git`，由扩展宿主 PATH 查找。每次命令可以重新读取 API 路径，失败不会永久缓存；超时或取消后的迟到结果不会改变已结束的调用。

路径来源变化时在扩展宿主日志记录 `[Git Branch Pruner] git-path:source=vscode.git`，或 `source=PATH reason=api-unavailable/api-timeout`，不输出完整本地路径。可在“输出”中选择 Extension Host（扩展宿主）查看。Git 命令自身的失败不会触发换用其他 Git 重跑，避免重复执行操作。独立业务测试默认仍使用 PATH，可注入明确路径或解析函数。

内置 Git 扩展的后台行为由 VS Code 自身设置控制；本插件仍仅在显式远端更新时调用 fetch。

## 自动化测试

```sh
pnpm test
pnpm run test:integration
```

- `pnpm test` 先编译，再用 Node test runner 运行 `src/test/unit/`：真实临时 Git 仓库、提交拓扑、删除保护、文件监听、超时取消、Webview 消息和状态保持。
- 测试隔离 Git 配置，remote 使用本地 bare 仓库，不 fetch 或删除开发仓库的分支。
- 原生文件监听需要操作系统权限；macOS 受限沙箱中即使单个 `fs.watch` 也可能报 EMFILE。此时应在正常终端运行，不能把跳过监听用例写成通过。
- `test:integration` 编译和打包后，用 `@vscode/test-cli` / `@vscode/test-electron` 启动隔离扩展宿主，测试文件路径为 `out/src/test/integration/`。
- 默认测试宿主可下载 VS Code。已有本地安装时设置 `BRANCH_PRUNER_VSCODE_PATH` 为实际可执行文件路径，避免下载。
- 设置 `BRANCH_PRUNER_TEST_WORKSPACE` 为专门创建、名字以 `branch-pruner-host-` 开头的空临时目录，启用本地优先加载/外部 fetch 的宿主测试。不要传入日常工作仓库。不提供该 fixture 时这一条测试会跳过。

## 手动验收

```sh
pnpm run demo
```

在项目的 `../tmp/demo/run-XXXXXX/` 下生成 repository、peer 和 remote.git 三个本地仓库，每次使用新的子目录，不覆盖旧环境。路径基于脚本所在项目解析。按 [手动验收清单](005.MANUAL_TESTS.md) 在扩展开发宿主中打开 repository，检查界面、外部操作自动同步和错误恢复。本轮用户负责实测；自动化测试不等于视觉验收。

## 打包与发布准备

`@vscode/vsce` 固定为开发依赖。执行 `pnpm run package` 时，`vsce` 会先调用 `vscode:prepublish`，完成 TypeScript 编译和 esbuild 生产构建，再生成 VSIX。扩展运行代码由 esbuild 打包，`vscode` 由宿主提供，因此打包使用 `--no-dependencies`，不携带 `node_modules`。

```sh
pnpm test
pnpm run package
```

版本为 `0.2.2` 时，默认生成项目根目录下的 `git-branch-pruner-0.2.2.vsix`。安装该包到普通 VS Code，使用 demo 验证中英文、首次加载、获取与取消和删除流程，再考虑发布。

`.vscodeignore` 排除源码、测试、开发文档、脚本、AI 开发工具配置目录和 pnpm 配置；保留 `dist/extension.js`、中英文资源、README、CHANGELOG、许可证、图标和截图。可用 `pnpm exec vsce ls --no-dependencies` 检查候选文件清单，生成后仍需核对实际 VSIX 内容。

`@types/vscode` 固定为 `1.80.0`，与最低宿主版本声明对齐。类型检查通过不等于已完成最低版本运行验证。`pnpm-workspace.yaml` 保存依赖构建脚本的批准策略，应和依赖清单、锁文件一起提交，不擅自开启所有脚本。

CHANGELOG 在实际发布前保留未发布标记。按用户 2026-10-27 的要求，代理只修改代码和执行测试验证，不执行发布。`pnpm run publish` 会上传 Marketplace，由用户自行操作；用户也可通过 Marketplace 管理页面上传已验收的 VSIX。VSIX、`out/` 和 `dist/` 不提交。CI、ESLint 和重复的 esbuild.js 清理仍待后续处理。

## 本地版本准备与手动发布

先完成代码、测试和文档修改，在 CHANGELOG 顶部写好目标版本及说明，例如 `## [0.2.2] - Unreleased`，再提交所有改动。工作区和暂存区必须干净。安装依赖后，由维护者执行：

```sh
./version.sh 0.2.2
# 可选的附注 tag 描述
./version.sh 0.2.2 "Release v0.2.2"
```

以上两条是二选一的调用方式，不要连续执行。脚本要求 Bash、Node、pnpm 和 Git，使用脚本所在仓库，不依赖调用时的目录。仅接受不带 `v` 的稳定版本号，允许当前 package.json 已是目标版本，不允许倒退；不会生成空白发布说明。已有日期保留，`Unreleased` 在本地版本准备时替换为当天日期。

脚本先检查本地 tag；存在 origin 时也只读检查远端 tag，远端不可达则在改文件前停止。然后更新根目录 package.json 和 CHANGELOG，运行 `pnpm test`、`pnpm run package`，成功后只提交这两个版本文件，并创建 `v0.2.2` 这样的附注 tag。若两个文件已无需修改，则直接标记当前提交，不生成空提交。产物为根目录 `git-branch-pruner-0.2.2.vsix`。已有同名包会被成功构建的新包替换。

失败时退出码非零，不推送、不发布、不自动回滚；可能留下版本文件修改、暂存内容或已完成的本地版本提交，请根据提示检查 `git status`。修正问题后，先检查并提交需要保留的内容，再重试。已存在的 tag 不会被覆盖。测试或打包期间出现其他源码改动、HEAD 改变，或提交钩子改变已验证内容时，不创建 tag。

安装生成的 VSIX，完成手动验收及需要的宿主测试后，由维护者推送源码和指定 tag，基于该 tag 在 GitHub 创建 Release，填写对应 CHANGELOG 内容并上传 VSIX。Marketplace 上传同一份文件，避免重新构建产生不同的同版本产物：

```sh
pnpm exec vsce publish --packagePath git-branch-pruner-0.2.2.vsix
```

发布由用户操作，代理不执行。脚本不检查 Marketplace 版本占用，准备前应确认版本尚未在市场发布。GitHub Release 从 0.2.2 开始；历史 tag 只有在能确认其对应源码时才补建。`version.sh` 和脚本测试均排除在 VSIX 之外。

脚本回归测试在临时仓库执行真实 Git 提交/tag，构建命令使用替身以验证失败路径；不会操作开发仓库的引用，也不会联网发布：

```sh
bash -n version.sh
node --test scripts/test-version.cjs
```

Codex 项目约定由根目录 `AGENTS.md` 提供，参考 [OpenAI 官方说明](https://developers.openai.com/codex/guides/agents-md)。
