## 当前优先事项（方案待确认）

1. **Windows 不再卡住**：采集系统、Git/VS Code 版本及具体停滞步骤，区分 Git 查找/启动、本地读取、监听初始化与显式 fetch；验证错误、取消和超时后进程结束、列表及按钮恢复。现有超时实现不能代替 Windows 实测；PATH 与 `git.path`、Windows 子进程终止及测试文件名兼容性均需核查。
2. **状态容易理解**：沿用实际 upstream 与 Ahead/Behind 的准确含义，讨论无上游、缓存引用缺失和刷新失败的说明，避免将同步或远端缺失表达成安全删除结论。多 remote 部分失败和缓存时效尚缺清晰表达。
3. **删除提示清楚**：沿用普通删除、显式强制删除及逐项结果，重点检查“只删除本地，不删除远端”是否足够醒目，以及长批量列表中的风险说明；具体文案与形式待确认，不默认增加确认次数。

## R2-03：创建本地分支（已暂停，移出本轮）

以下仅保留旧设计记录。尚无产品创建分支功能实现，不作为当前开发或验收要求；只有后续明确重新纳入范围才继续。

建议的第一版交互：

- 顶部增加“新建分支”入口，默认从当前 HEAD 创建，并清楚显示起点。
- 输入分支名，提供“创建后切换”选项，建议默认开启；用户也可以只创建。
- 校验名称与本地重名，兼容 `feature/example`、中文及其他合法名称。
- 取消输入不产生任何改动，成功后列表自动出现新分支；若切换成功则同步当前标记。
- 只创建本地分支，不自动推送，也不自动设置远端上游。
- 操作绑定发起时的仓库与起点；输入期间发生外部切换时，不能悄悄改用另一仓库或起点。

异常处理：

- 重名或 refs 路径冲突明确提示，禁止覆盖已有分支。
- 切换失败不强制丢弃或自动暂存未提交改动，按实际结果说明分支是否已经创建。
- detached HEAD 有有效提交时可从该提交创建；无提交仓库给出明确提示。
- 采用安全参数传递，名称作为数据，不拼接 shell。

验收：正常创建、创建并切换、仅创建、取消、非法名称、重名、路径冲突、特殊字符、起点变化和失败路径均有适当测试；用户验证基本创建流程。这是暂停前的验收建议，当前不执行。
