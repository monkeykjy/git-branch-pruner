## 1. 目标

把现有功能收敛为一个稳定、轻量、快捷的本地 Git 分支清理工具：用户能看懂本地分支及其实际上游状态，能安全选择并批量删除本地分支，且在 Windows、离线或远端更新失败时不会无限卡住或误报状态。

本阶段优先级固定为：

1. Windows 可用性和操作可恢复性。
2. 分支状态表达准确、容易理解。
3. 删除影响范围和风险提示清楚。
4. 现有功能的自动化和用户验收收口。

## 2. 建设范围

### 2.1 Windows 稳定性

为本地读取、远端更新和 Webview 初始化建立可观察、可结束的流程：

- 区分 Git 可执行文件启动、仓库发现、Git 元数据目录读取、分支状态读取、文件监听初始化和 fetch 阶段。
- 本地读取流程支持统一的超时、取消和失败恢复，不能让界面永久停留在 loading。
- 保留 Git 参数数组执行、代理和认证配置继承，不修改用户全局配置，不强制使用或清除代理。
- 验证 Windows 上 Git PATH、VS Code `git.path` 配置、中文/空格/长路径和 linked worktree 的行为。
- 超时或取消后确认 Git 进程及其子进程已结束，控件恢复可操作，已有本地状态仍可查看。
- 对 Git 启动失败、读取失败、fetch 失败、取消和超时给出可重试的通用提示，避免展示凭据或敏感远端信息。

### 2.2 状态表达

继续以实际 upstream 为比较对象，Ahead / Behind 表示两侧各自独有的 commit 数量。状态模型保持以下区别：

| 状态 | 用户可见含义 |
| --- | --- |
| 当前、受保护、工作树使用中 | 该分支不应被当前操作删除 |
| 未设置上游 | 没有比较目标，不显示虚假 `0 / 0` |
| 跟踪本地分支 | 比较目标是另一个本地分支 |
| Ahead / Behind | 相对该分支实际 upstream 的 commit 差距 |
| 已同步 | Ahead 和 Behind 都为 0 |
| 本地未找到上游引用 | 本地缓存中没有比较对象，不能直接证明远端已删除 |
| 远端更新失败、超时或取消 | 继续显示本地引用；部分引用可能已更新，不能确认所有远端状态 |

每个远程跟踪分支显示具体比较对象，例如 `origin/feature/login`。状态本身不等于“已合并”或“可以安全删除”；普通删除继续由 Git 的未合并保护决定。

### 2.3 删除提示与结果

保留普通删除和强制删除两种明确区分的操作，不增加不必要的确认层级：

- 普通删除使用 `git branch -d`，未合并分支由 Git 拒绝并保留。
- 强制删除使用 `git branch -D`，单独确认并明确说明可能丢失未合并提交的分支引用。
- 确认内容醒目说明：**只删除本地分支，不删除远程分支。**
- 确认内容列出目标分支、操作模式、受保护分支和 worktree 分支仍会被保留的规则。
- 服务层在执行时重新验证当前分支、保护分支、worktree 占用和目标是否仍存在。
- 批量操作逐项返回结果，失败不被吞掉，也不自动升级为强制删除。

### 2.4 既有能力收口

搜索、切换、本地刷新、显式远端更新、外部 Git 引用自动重读和紧凑列表样式继续保留，先完成用户验收，再决定搜索和切换是否长期存在。界面不扩展为完整 Git 管理器。

## 3. 实施顺序

### 阶段一：Windows 诊断与可恢复性

先收集 Windows 系统、VS Code、Git 版本，以及具体卡住操作和停滞阶段。然后只针对有证据的阶段增加超时、取消、错误分类或可选 Git 路径支持。完成标准是任何初始化、刷新或 fetch 操作都有结束路径，失败后仍能重试或查看已有本地状态。

2026-10-19 已完成初步处理：本地初始化链路增加 15 秒整体截止时间；取消信号传入 Git 状态读取和监听目录扫描；超时后显示可重试错误或保留上次列表；阶段日志写入 VS Code 的 `Git Branch Pruner` 输出通道。日志只记录阶段、耗时、平台、数量和错误类型，不记录完整路径、凭据或远端 URL。Windows 排查确认曾运行旧 dist，重新打包后本地读取与远端更新均有成功日志，用户确认当前已正常。此前卡住的完整根因未被证明；超时、取消、特殊路径等未测项不写成通过，按用户决定不阻塞后续 macOS 工作。

### 阶段二：状态文案和缓存时效

以真实 upstream、Ahead / Behind、无上游、上游引用缺失、fetch 失败/取消为最小状态集合，统一中英文说明和比较目标展示。不得把本地缓存缺失写成已确认的远端删除，也不得把状态标签写成安全删除结论。

当前实现：保留已验收紧凑列表；缺失状态改为“本地未找到上游引用”；常驻说明明确数据不是远端实时查询。手动 fetch 完成记录当前会话的日期和时间，说明获取范围遵循 Git 配置，外部 fetch 或本地刷新不更新该时间。失败、超时、取消提示可能存在部分引用更新；远端结果与切换等操作提示分开保存，不被本地刷新或切换失败覆盖。外部引用仍自动重读，不将监听到变化当成一次成功的远端获取。

### 阶段三：删除范围提示

在现有确认和逐项结果基础上，调整“只删除本地、不删除远端”及强制删除风险的突出程度，检查长分支名、批量列表和窄侧栏可读性。服务层保护规则不由界面禁用状态替代。

## 4. 不在本阶段建设

- 创建本地分支。
- 删除远程分支、自动清理、自动 pull/push 或后台联网轮询。
- 合并/rebase 判断、squash/rebase 智能推断、提交历史图和 diff 查看器。
- AI 清理建议、完整 Git 管理器式导航、仓库选择、自定义保护规则和复杂筛选。
- 强制覆盖代理、认证或 Git 全局配置。
- Marketplace 发布、自动发布和未经用户指令的 commit/push。

## 5. 验收标准

### 自动化

- 首次读取和自动监听不执行 fetch；只有显式远端更新才 fetch。
- 正确覆盖实际 upstream、非 `origin` remote、不同名 upstream、无 upstream、引用缺失、detached HEAD 和空仓库。
- 覆盖当前分支、main/master、远程默认分支和 linked worktree 的保护。
- 覆盖普通删除、强制删除、混合批量结果、失败重试和特殊分支名。
- 覆盖 Git 启动失败、读取超时、fetch 超时、取消和控件恢复。
- 覆盖外部 checkout、分支变化和 fetch 后的状态重算，以及搜索、有效选择和滚动位置保持。

### Windows 手动验收

- Git 不在 PATH 或 Git 路径配置异常时，不无限 loading，并给出可操作错误。
- 正常仓库首次打开、本地刷新、显式 fetch、fetch 失败、取消和超时后都能恢复操作。
- 外部终端执行 checkout、branch、fetch 后界面能更新。
- 中文路径、空格路径、长路径、特殊字符分支名和 linked worktree 可用。
- 失败时列表和已有缓存状态不被误报为远端已刷新。

### 用户体验验收

- 窄侧栏和长分支名仍可读，中英文标签不互相遮挡。
- Ahead / Behind 与比较对象容易理解，无 upstream 不出现虚假数字。
- 删除确认在目标列表前明确显示只删除本地、不删除远端；普通和强制删除风险有明显区别。
- 删除结果能逐项说明成功、未合并、受保护、worktree 占用、已不存在或失败。

## 6. 关键假设和风险

本计划假设卡住问题来自 Git 启动、仓库读取、文件监听或子进程终止路径之一。如果 Windows 实测证明根因在 VS Code 宿主或特定 Git 安装环境，先保留阶段性诊断和可重试错误，再据证据决定是否扩大实现范围；不能仅凭其他平台通过就宣称 Windows 已解决。

本计划预计涉及现有 GitRunner、GitService、BranchPrunerViewProvider、RepositoryWatcher、Webview 和对应测试/文档，但不引入新的服务或运行时。所有修改都应可通过恢复旧文案或回退单个提交撤销，不改变用户仓库历史、不删除远程引用。
