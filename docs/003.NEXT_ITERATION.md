## 实施顺序

按以下四个工作包顺序落地，每包有独立验证和可审阅的改动。工程工作先满足修复需要，不先做无关工具链重构。

### 工作包 1：测试基础与输入安全

对应问题：B01、B03、B10、B12。

改动范围：Git 执行层、Webview 渲染和消息入口、测试配置与必要依赖。

- 抽出可以脱离 VS Code UI 测试的 Git 命令执行接口，保留现有 service/provider 的职责划分。
- 使用 `execFile` 或 `spawn`，参数数组传递命令；避免 shell，移除 Windows 中任意命令失败后换 shell 重试的逻辑。
- 测试使用临时仓库和本地 bare remote，隔离测试 Git 配置并清理临时数据。
- 修正测试发现路径，区分不启动 VS Code 的 Git 行为测试与扩展宿主集成测试。
- 分支名通过文本节点或适当转义渲染；为 Webview 设置 CSP，并调整内联事件处理方式。
- 校验 Webview 消息类型、分支数组和每个元素的类型；拒绝非法消息，避免未捕获的异步错误。

验收：特殊字符分支名可原样列出和传入 Git，不产生命令副作用；HTML 字符按文本显示；无效消息不能触发删除；测试数量大于零，且对上述行为作实际断言。Windows 至少验证无需 bash 和失败不重复执行。

### 工作包 2：删除保护与结果反馈

对应问题：B02、B04、B09。

改动范围：GitService、Branch 类型、删除确认和批量结果界面。

- 默认使用保留 Git 未合并保护的删除方式。强制删除作为明确区分的用户操作，不在普通删除失败后自动升级。
- 执行前重新读取分支与 worktree 状态；保护当前分支、main、master 和能够识别的远程默认分支；强制模式也不绕过这些保护。
- 校验目标是当前操作仓库中存在的本地分支；一次操作固定仓库路径，避免工作区变化影响目标。
- 返回逐项结果，区分成功、不存在、受保护、worktree 占用、未合并和其他失败；不再以 `void` 吞掉失败。
- 删除后只刷新本地状态，不让删除结果等待网络 fetch。

验收：有未合并提交的分支在普通删除下保留；main/master 同时存在时均被保护；worktree 占用分支保留；混合批量操作中每项结果准确，调用方能感知失败。

说明：`git branch -d` 自身的合并检查可能相对 upstream 或 HEAD，不能据此宣传“已经合并进主分支”。当时建议在工作包 4 增加显式的目标分支合并判断；尚未实现，也未纳入当前确定范围。

### 工作包 3：网络刷新、代理继承和错误恢复

对应问题：B08；同时改善网络等待与错误页面。

改动范围：Git 执行选项、列表加载流程、进度取消、远程状态元数据。

- 先展示本地列表和已有远程跟踪信息；远程更新单独触发，不让首次显示或本地删除依赖网络成功。
- 保留用户现有 Git 配置和代理环境，不硬编码代理地址、不强行清空代理、不修改用户全局 Git 配置。
- Git 执行增加超时与取消。建议初值：本地查询 10 秒、fetch 30 秒；超时策略集中管理，按真实验证调整。
- 取消/超时必须结束对应 Git 任务并恢复控件；验证子进程清理，不能只解除界面等待。
- 返回 fetch 结果、最后成功时间和适用 remote；失败后保留本地列表，持续标记“远程状态未更新”，提供重试入口。
- 对连接、代理、认证、超时等常见错误提供可操作的提示，无法分类时保留通用失败原因；日志隐藏凭据与敏感 URL 内容。
- 明确这个插件调用的是外部 Git：不能假设 VS Code 的 `http.proxy` 会自动配置该子进程。

验收矩阵：无代理、有代理、无效代理、离线、认证失败、超时、用户取消。环境继承使用受控变量断言；连接故障使用注入或本地 fixture，不依赖公共网络。各场景下本地列表仍可用，缓存状态不会伪装成已刷新结果。

### 工作包 4：分支状态准确性与交付检查

对应问题：B05、B06、B07、B11，以及当前缺少合并判断的功能缺口。

改动范围：结构化 refs 读取、Branch 数据模型、状态标签、测试与打包配置。

- 使用 `for-each-ref` 等结构化输出获取本地分支和 upstream；worktree 信息单独读取，不解析 `git branch` 的展示标记。
- 区分未设置 upstream、upstream 引用缺失、upstream 引用存在，以及远程数据是否已更新。缺少 upstream 不等同于“从未推送”。
- 支持 remote 不叫 origin、跟踪分支与本地不同名等场景；远程刷新针对实际使用的 remote 记录结果。
- 用独立的 HEAD 状态表示 detached HEAD，不生成虚假分支条目；空仓库与读取失败分别展示。
- 对有效 upstream 计算 ahead/behind；合并判断明确标注目标分支。第一版以提交祖先关系为依据，对 squash/rebase 合并不自动宣称可安全删除。
- 衔接编译、业务测试和 VSIX 打包，补齐必要工具依赖；在 CI 中运行核心检查。更新中英文说明与变更记录。

验收：非 origin 与不同名 upstream 正确匹配；worktree 和 detached HEAD 不污染分支名；失败不显示为真实空列表；合并与领先/落后结果有可解释的参照对象。干净环境可以生成包含最新扩展入口的 VSIX。

## 暂定产品规则

下面是用于收敛实施范围的建议，不是已经实现的行为：

- 初次打开先读取本地状态，用户通过明确的远程更新操作获取最新远程信息。
- main、master、当前分支、worktree 占用分支和可识别的远程默认分支纳入保护；自定义保护规则后续增加。
- 合并目标优先识别远程默认分支，无法唯一确定时提示用户选择；不随意选择一个分支给出安全结论。
- 第一版只承诺基于 Git 提交关系的判断，不把 squash/rebase 后的表面差异当作可自动清理证据。
