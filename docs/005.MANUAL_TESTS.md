## 准备

在项目根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm run compile
pnpm run build:esbuild
pnpm run demo
```

最后一条命令在项目的 `../tmp/demo/` 下创建独立的 `run-XXXXXX/` 环境并打印路径：`repository` 是待测仓库，`peer` 模拟另一个开发者，`remote.git` 是本地 bare 远程仓库。位置相对源码项目固定，不依赖执行命令时的目录；重复生成不会覆盖旧环境。下文的 `<repository>` 和 `<peer>` 请替换为实际路径；命令中的双引号保留。

```text
../tmp/demo/run-XXXXXX/
├── repository/
├── peer/
└── remote.git/
```

在 VS Code 打开扩展源码项目，按 F5 启动 `Run Extension`。在新开的 **Extension Development Host** 窗口打开上面生成的 `repository` 文件夹，再打开 Git Branch Pruner 侧栏。若修改代码后重新测试，先重启或重载扩展开发宿主。

为了区分插件行为和 VS Code 自带 Git 的自动 fetch，本地优先测试时检查测试窗口中的 `git.autofetch` 是否关闭。插件不会更改这个设置。

## 1. 首次打开与比较对象

预期列表首先显示本地分支，当前为 main，没有主动访问远端的进度通知。数字来自已经保存的远程引用。

| 分支 | 初始预期 |
| --- | --- |
| main | 当前、受保护、已同步；比较 origin/main |
| master | 受保护、未设置上游 |
| feature/ahead | Ahead 2 · Behind 0 |
| feature/behind | Ahead 0 · Behind 2 |
| feature/diverged | Ahead 3 · Behind 2 |
| feature/gone | 初次读取缓存时已同步，远端实际已删除，等待手动更新 |
| local-only | 未设置上游，不显示虚假的 0/0 |
| delete-safe | 未设置上游，可用于普通删除 |

重点检查每行是否注明 `origin/...` 比较对象，窄侧栏、长分支名和中文/英文界面是否可读。

## 2. 切换和创建的自动跟随

- 在列表中点击 local-only 的“切换”：当前标记应立即移动，该分支移到列表顶部。
- 在终端执行 `git -C "<repository>" switch main`：无需点击刷新，当前标记自动回到 main。
- 执行 `git -C "<repository>" branch feature/external-created`：新分支自动出现。
- 执行 `git -C "<repository>" branch -d feature/external-created`：该分支自动消失。
- 可用 VS Code 自带 Git 界面切换一次，确认结果相同。

## 3. 外部 fetch 自动更新数字

先让模拟远端再增加一个提交：

```sh
git -C "<peer>" switch feature/behind
git -C "<peer>" -c user.name=Demo -c user.email=demo@example.invalid commit --allow-empty -m "another remote commit"
git -C "<peer>" push
```

repository 尚未 fetch，插件仍应显示 Behind 2，不应自行联网。随后执行：

```sh
git -C "<repository>" fetch --prune origin
```

无需点击插件按钮，feature/behind 应变为 Behind 3，feature/gone 应显示上游引用已消失。外部 fetch 不应被标记成插件刚完成的手动更新。

## 4. 手动更新与交互保留

- 点击“更新远端状态”：列表保留，显示可取消的进度，结束后显示手动更新成功时间。
- 搜索 `feature`，勾选 feature/ahead，并滚动列表。在外部创建一个分支或执行 fetch 后，搜索、仍有效的勾选和滚动位置应保留。
- 点击“刷新本地”只重读本地，不出现远端更新进度。
- 清空搜索、取消勾选后，两种删除按钮都应禁用；全选不应选中受保护分支。

## 5. 删除保护

- 选择 delete-safe → 普通删除 → 确认：分支消失，结果显示已删除。
- 选择 feature/ahead → 普通删除 → 确认：分支保留，结果显示尚未合并。
- 再选择 feature/ahead → 强制删除：弹窗应明确说明跳过合并检查；先取消一次，确认分支仍存在且勾选保留。仅在这个临时仓库中再次确认强制删除，分支应消失。
- main、master、当前分支不可勾选。
- 用 `git -C "<repository>" worktree add -b feature/worktree "<另一个不存在的临时目录>"` 创建工作树：feature/worktree 应标记为使用中，不能删除或在原仓库切换到它。

## 6. 离线/远端失败

先记录 demo 打印的 remote 路径，然后仅在临时 repository 中执行：

```sh
git -C "<repository>" remote set-url origin /a/nonexistent/branch-pruner-test-remote
```

- 重载侧栏：本地列表仍应正常显示，不因无效远端卡住。
- 点击“更新远端状态”：应提示失败并保留本地列表、已有数字；随后仍可刷新本地和切换分支。
- 恢复：`git -C "<repository>" remote set-url origin "<原 remote 路径>"`，再更新应成功。
- 慢网络下的取消与 30 秒超时，可在可控测试 remote 上补验；快速返回的本地 remote 通常来不及点击取消。不要为测试改动全局代理。
