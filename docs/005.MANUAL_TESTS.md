## 准备

在项目根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm run compile
pnpm run build:esbuild
pnpm run demo
```

最后一条命令在项目的 `../tmp/demo/` 下创建独立的 `run-XXXXXX/` 环境并打印路径：`repository` 是待测仓库，`peer` 模拟另一个开发者，`remote.git` 是本地 bare 远程仓库。位置相对源码项目固定，不依赖执行命令时的目录；重复生成不会覆盖旧环境。下文的 `<repository>` 和 `<peer>` 请替换为实际路径；命令中的双引号保留。

```text
../tmp/demo/run-XXXXXX/
├── repository/
├── peer/
└── remote.git/
```

在 VS Code 打开扩展源码项目，按 F5 启动 `Run Extension`。在新开的 **Extension Development Host** 窗口打开上面生成的 `repository` 文件夹，再打开 Git Branch Pruner 侧栏。若修改代码后重新测试，先重启或重载扩展开发宿主。

为了区分插件行为和 VS Code 自带 Git 的自动 fetch，本地优先测试时检查测试窗口中的 `git.autofetch` 是否关闭。插件不会更改这个设置。

## 1. 首次打开与比较对象

预期列表首先显示本地分支，当前为 main，没有主动访问远端的进度通知。数字来自已经保存的远程引用。

| 分支 | 初始预期 |
| --- | --- |
| main | 当前、受保护、已同步；比较 origin/main |
| master | 受保护、未设置上游 |
| feature/ahead | Ahead 2 · Behind 0 |
| feature/behind | Ahead 0 · Behind 2 |
| feature/diverged | Ahead 3 · Behind 2 |
| feature/gone | 初次读取缓存时已同步，远端实际已删除，等待手动更新 |
| local-only | 未设置上游，不显示虚假的 0/0 |
| delete-safe | 未设置上游，可用于普通删除 |

重点检查每行是否注明 `origin/...` 比较对象，窄侧栏、长分支名和中文/英文界面是否可读。

## 2. 切换和创建的自动跟随

- 在列表中点击 local-only 的“切换”：当前标记应立即移动，该分支移到列表顶部。
- 在终端执行 `git -C "<repository>" switch main`：无需点击刷新，当前标记自动回到 main。
- 执行 `git -C "<repository>" branch feature/external-created`：新分支自动出现。
- 执行 `git -C "<repository>" branch -d feature/external-created`：该分支自动消失。
- 可用 VS Code 自带 Git 界面切换一次，确认结果相同。

## 3. 外部 fetch 自动更新数字

先让模拟远端再增加一个提交：

```sh
git -C "<peer>" switch feature/behind
git -C "<peer>" -c user.name=Demo -c user.email=demo@example.invalid commit --allow-empty -m "another remote commit"
git -C "<peer>" push
```

repository 尚未 fetch，插件仍应显示 Behind 2，不应自行联网。随后执行：

```sh
git -C "<repository>" fetch --prune origin
```

无需点击插件按钮，feature/behind 应变为 Behind 3（中文“落后 3”），feature/gone 应显示“本地未找到上游引用”。外部 fetch 不应被标记成插件刚完成的手动更新。

## 4. 手动更新与交互保留

- 点击“更新远端状态”：列表保留，显示可取消的进度，结束后显示本次会话手动 fetch 完成的日期和时间，并说明获取范围遵循 Git 配置。此时间不保证服务器当前状态；外部 fetch 或本地刷新不会更新它。
- 搜索 `feature`，勾选 feature/ahead，并滚动列表。在外部创建一个分支或执行 fetch 后，搜索、仍有效的勾选和滚动位置应保留。
- 点击“刷新本地”只重读本地，不出现远端更新进度。
- 清空搜索、取消勾选后，两种删除按钮都应禁用；全选不应选中受保护分支。

## 5. 删除保护

- 第三阶段新增检查：普通/强制确认都应首先展示“只删除本地分支，不删除远程分支”，随后是模式风险与当前/受保护/worktree 保留规则，仓库和完整编号目标列表放在后面。确认按钮明确标注本地分支，不增加确认次数。批量选择和长分支名应可完整核对；这项可点击取消，不必重复删除已验收的分支。
- 选择 delete-safe → 普通删除 → 确认：分支消失，结果显示已删除。
- 选择 feature/ahead → 普通删除 → 确认：分支保留，结果显示尚未合并。
- 再选择 feature/ahead → 强制删除：弹窗应明确说明跳过合并检查；先取消一次，确认分支仍存在且勾选保留。仅在这个临时仓库中再次确认强制删除，分支应消失。
- main、master、当前分支不可勾选。
- 用 `git -C "<repository>" worktree add -b feature/worktree "<另一个不存在的临时目录>"` 创建工作树：feature/worktree 应标记为使用中，不能删除或在原仓库切换到它。

## 6. 离线/远端失败

先记录 demo 打印的 remote 路径，然后仅在临时 repository 中执行：

```sh
git -C "<repository>" remote set-url origin /a/nonexistent/branch-pruner-test-remote
```

- 重载侧栏：本地列表仍应正常显示，不因无效远端卡住。
- 点击“更新远端状态”：应提示失败并保留本地列表，说明部分引用可能已更新，不能确认所有远端状态；随后仍可刷新本地和切换分支，失败提示仍保留。多 remote 场景中，可用 remote 的数字可能已改变，不要求所有数字保持旧值。
- 恢复：`git -C "<repository>" remote set-url origin "<原 remote 路径>"`，再更新应成功。
- 慢网络下的取消与 5 分钟超时，可在可控测试 remote 上补验；快速返回的本地 remote 通常来不及点击取消。不要为测试改动全局代理。

## 7. 慢速获取、取消和超时（macOS 本地模拟）

此前用户已接受等待和取消交互；此前 30 秒硬超时的本地模拟记录保留为历史。2026-10-19 Windows 某仓库主动获取连续达到 30 秒截止时间，另一仓库可成功。用户确认调整为 30 秒软提示、5 分钟硬超时；原 Windows 仓库需使用更新后的安装包验证，不能据其他仓库成功直接确认根因。

新生成的 demo 在 run 目录包含 `slow-upload-pack.sh`。旧脚本只支持 8/35 秒，仍可用于等待和取消检查；验证 305 秒超时场景需要使用更新脚本生成的新 demo，原环境会保留。以下命令仅在新 demo 的 `repository` 终端执行；不修改全局代理、网络配置或真实项目。

```sh
git config remote.origin.uploadpack "sh ../slow-upload-pack.sh 8"
```

1. 点击插件“更新远端状态”：侧栏立即显示加载图标、已等待秒数和取消按钮，列表保留，可搜索；切换、删除、选择和重复获取暂时禁用。约 8 秒后获取结束，获取计时和取消按钮消失；本地重读期间显示“正在刷新本地状态”，完成后按钮恢复。读取较快时该阶段可能一闪而过。
2. 再次获取，等待两三秒后点击侧栏“取消获取”：先进入取消中状态，Git 结束后显示取消结果，按钮恢复，可再次获取。远端获取不再弹出右下角进度通知，状态和取消统一在侧栏展示（用户已确认通过）。Git 结束后若本地重读较慢，应显示本地刷新阶段，不继续累计获取时间或显示取消获取按钮。
3. 超过 30 秒的成功检查：执行下方 35 秒配置。到 30 秒显示“获取时间较长，可继续等待或取消”，计时继续，取消按钮可用，其他操作仍禁用；约 35 秒后应成功结束并恢复操作。可再次获取，在提示出现后取消，验证仍能恢复。

```sh
git config remote.origin.uploadpack "sh ../slow-upload-pack.sh 35"
```

4. 可选超时检查：新 demo 使用 305 秒配置，30 秒后继续等待，约 5 分钟触发超时并恢复操作。该测试较慢，不必每次重复。

```sh
git config remote.origin.uploadpack "sh ../slow-upload-pack.sh 305"
```

结束后还原，并再次点击获取确认恢复正常速度：

```sh
git config --unset remote.origin.uploadpack
```

这里只模拟 Git 传输响应慢，不等于真实网络/认证环境的完整验收。加载图标不表示准确完成比例；减少动态效果的系统偏好启用时图标静止，等待文字继续更新。

## 0.2.1 获取错误详情补验

在可丢弃 demo 中复现获取失败（或使用已知会报错的仓库），点击“更新远端状态”：侧栏应展开 Git 错误详情，显示具体分支/引用错误和退出码，允许选中复制；输出通道也应记录 `remote-update:details`。不应只显示网络、代理或认证建议。URL 和常见认证字段显示为脱敏标记；长文本换行、滚动，不挤宽侧栏。

点击“刷新本地”后详情仍在，列表与操作可用；修正 demo 配置后再次获取，旧详情立即清除，成功后显示完成信息。中文与英文各检查一次。取消及超时仍显示各自的提示，不冒充普通 Git 失败。此项不要求删除任何分支。
