# Git Branch Pruner

一个轻量、可视化的本地 Git 分支清理扩展。

[English](README_EN.md) | 简体中文

## 功能特性

- 打开侧栏立即读取本地分支，不自动 fetch。
- 展示每个分支与实际远端上游的 Ahead / Behind，单位为 commit。
- 自动跟随终端或其他 Git 工具的切换、提交、分支创建/删除及 fetch 等引用变化。
- 搜索、切换、批量删除本地分支，自动刷新保留有效选择与滚动位置。
- 普通删除保留 Git 的未合并保护；强制删除有独立入口和确认。
- 支持中文和英文界面。

## 使用方法

1. 在 VS Code 打开一个 Git 仓库，进入 Git Branch Pruner 侧栏。
2. 查看本地分支和缓存的上游差距；当前分支置顶。默认管理工作区的第一个文件夹。
3. 点击“更新远端状态”执行 `git fetch --all --prune`，之后重新计算差距。此操作不 pull、merge 或推送。
4. “刷新本地”只重读本地状态；外部 Git 操作发生后通常无需手动刷新。
5. 使用“切换”切换本地分支，或勾选分支后删除。失败时不会自动丢弃工作区改动或升级为强制操作。

## 状态说明

- **Ahead 3 · Behind 2**：本地有 3 个上游未包含的提交，上游有 2 个本地未包含的提交。
- **已同步**：本地与配置的远端上游没有独有提交。
- **未设置上游**：没有配置比较对象，不显示虚假的 0/0。
- **上游引用已消失**：本地保存的上游引用不存在，不代表该本地分支可以安全删除。
- **当前 / 受保护 / 工作树使用中**：相关分支禁止删除。

比较对象显示在分支行中，例如 `origin/feature/login`；不是统一与 main 比较。数字基于本地已有的 Git 历史和远程跟踪引用，浅克隆只能反映当前已获取的历史。点击远端更新或外部工具执行 fetch 后，才会获得服务器的新信息。插件不后台轮询远端，也不强制设置或清空代理；沿用 Git 环境和配置。

远端更新期间保留列表，支持取消，30 秒超时后提示；失败或取消后仍显示已有引用。多个 remote 使用 Git 的 `--all` 行为，包括其 `skipFetchAll` 配置。

## 删除保护

- 普通删除使用 `git branch -d`。Git 按上游或 HEAD 判断是否完全合并，不能据此宣称已经合并进默认分支。
- 强制删除使用 `-D`，可能移除指向未合并提交的分支引用，需要单独确认。
- 当前分支、main/master、根据本地 remote HEAD 识别的默认分支及工作树占用分支均由执行层保护，强制模式也不绕过。
- 批量操作逐项展示成功或未删除的原因，只操作本地分支。

## 系统要求与开发

- VS Code 1.80.0 或更高版本。
- Git 2.40.0 或更高版本，并可在 PATH 中找到。
- 开发和测试使用 Node.js 22、pnpm；详见 [开发说明](docs/002.DEVELOPMENT.md)。
- 使用 `pnpm run demo` 在项目的 `../tmp/demo/run-XXXXXX/` 下生成独立的本地测试环境，按 [手动验收清单](docs/005.MANUAL_TESTS.md) 测试。
